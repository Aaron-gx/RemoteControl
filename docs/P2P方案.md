# P2P 直连方案（直连优先 + 中继兜底）

> **状态：✅ 有效**（与架构定稿兼容：P2P 只影响传输路径，不影响共享/多会话模式）。

> 现状：`主控端 ⇄ 香港中继 ⇄ 被控端`，所有流量都过中继。
> 目标：能直连就直连（延迟更低、不吃服务器带宽），直连不了就自动回落中继 —— **中继永远保留**。

## 一、为什么中继必须保留（不是"过渡方案"）

1. **信令**：双方都不知道对方的公网地址，必须有个共同可达的点先交换地址。
2. **兜底**：对称型 NAT / 企业防火墙 / 运营商级 NAT 下打洞会失败，此时只能转发。
3. **文件暂存**：剪贴板文件走 HTTP 暂存，比 P2P 传文件简单可靠（10 分钟自动清理）。
4. 现实中 RDP/TeamViewer/AnyDesk 都是这个结构：**打洞优先，失败回落自有中继**。

## 二、三级连接策略（按成本从低到高，逐级尝试）

| 级别 | 场景 | 做法 | 成本 |
|---|---|---|---|
| L1 直连 | 同一局域网；或一方有公网 IP/已端口映射 | 信令交换内网 IP 与公网 endpoint，直接 TCP 连 | 低（几十行） |
| L2 打洞 | 双方都在 NAT 后（家庭宽带典型） | UDP 打洞：双方同时向对方公网 endpoint 发包建立映射 | 中（UDP 传输层 + 可靠性） |
| L3 中继 | 对称 NAT / 企业网 / 打洞失败 | 现有 WebSocket 中继 | 已实现 |

## 三、只需中继增加的一点点改动（信令）

中继天然知道双方的公网 endpoint（WS 连接的 `RemoteAddr`）。加两条控制消息即可：

```
服务器 → 双方：  {"type":"peer","endpoint":"1.2.3.4:51234","role":"agent"}
```

- 被控端上线时把自己的**内网候选**（本机各网卡 IP + 监听端口）通过 WS 报给中继
- 主控端连接后，中继把被控端的候选列表推给主控端，同时把主控端的公网 endpoint 推给被控端
- 双方拿到候选后按 L1 → L2 → L3 顺序尝试；任一级成功即切换，失败继续用中继（**不打断会话**）

## 四、直连通道怎么跑协议

现有线上协议是"消息流"（`[1B 类型][4B 长度][负载]`），与传输无关：

- 把 WS 换成一条 TCP 连接（L1）或一条可靠的 UDP 会话（L2）即可复用同一套编解码
- 切换时发一次 `0x13 StreamReset`，让编码器/解码器重建（已有机制）

## 五、L2（UDP 打洞）的工程量与风险

| 项 | 说明 |
|---|---|
| UDP 传输层 | 需要自己实现：分片/重组、ACK、重传、拥塞控制（或直接引 quic-go / KCP） |
| 打洞 | 双方各发若干个"打孔包"到对方公网 endpoint，随后互测心跳 |
| 加密 | 直连没有中继的 TLS，需在信令阶段用中继通道做 ECDH 换密钥（否则明文视频） |
| NAT 类型探测 | 至少区分"锥形 / 对称"，对称直接跳过 L2 省时间 |
| 实测环境 | **必须在真实 NAT 环境验证**（你的香港服务器 + 两台不同网络的机器）：单机无法验证打洞 |
| 建议库 | `quic-go`（Go 侧）+ 主控端用 .NET 的 QUIC（net8 自带 `System.Net.Quic`），开箱即有可靠传输与加密 |

## 六、建议的落地顺序

1. **先部署香港中继**（已备好一键脚本）→ 立刻可用，跨网络就能控制别人的电脑
2. **加 L1 直连**（低风险、覆盖"同一局域网/有公网 IP"这两个很常见的情况，一天量级）
3. **再加 L2 打洞 + QUIC**（真正的 P2P，需要你的服务器 + 真实网络联调；工程量较大）
4. 任何一级失败都自动回落 L3，**用户无感**

## 七、我会怎么验收 P2P

| 验收项 | 方法 |
|---|---|
| L1 直连成立 | 同机/同网段：抓包或日志确认媒体流量不过中继（中继侧字节数≈0） |
| L2 打洞成立 | 两台不同网络（例：家里 + 手机热点/云主机）互连，日志显示 direct=true，且中继侧无媒体流量 |
| 回落正确 | 人为屏蔽直连端口 → 3 秒内自动回落中继，画面不断 |
| 切换无感 | 直连建立过程中画面不卡死；切换后 `StreamReset` 一次，无花屏 |
| 加密 | 直连抓包看不到明文画面/键鼠内容 |

## 八、结论（我的建议）

- **先做 L1 + 中继兜底**：性价比最高，能覆盖"两台电脑在同一局域网"这类高频场景；跨网仍走香港中继（体验可接受）。
- **L2 打洞** 等中继部署完、双方都在真实网络里跑起来后再上，因为它的成败只能靠真实 NAT 实测，评估成本低、返工风险小。
- 无论哪一步，**中继都不能撤**：它是信令 + 兜底 + 文件暂存三合一。
