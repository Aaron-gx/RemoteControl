# 运维文档 · 授权（时间限制）与防绕过

> 本文件是**厂商侧**文档：讲激活码怎么签发/安装、时间限制怎么防绕过。
> 面向最终用户的使用说明在 `使用说明.md`，其中**不含**任何授权相关内容
> （主控端与被控端的界面上也都不显示授权信息）。

## 一、授权（时间限制）

中继服务器带**时间限制**：授权到期后中继会拒绝一切通信（`/healthz` 除外，便于排障），
需要新的激活码才能继续用。

### 怎么填激活码（两种方式，任选）

**方式一：网页（推荐，浏览器里粘贴即可）**

1. 上位机 `LicenseKeygen.exe` 里点「生成激活码」（默认参数已填好：自动读服务器部署ID、
   授权编号自动+1、有效期默认一年），点「复制」
2. 浏览器打开：`http://202.60.232.209:8080/admin?token=<管理令牌>`
3. 把激活码粘进文本框 → 点「安装/续期」→ 页面会显示新的状态与剩余天数

> 这个页面**在授权过期后照样能打开**（授权闸门特意放行 `/admin`），
> 否则服务器一到期就再也没法进去续期了。页面需要**管理令牌**（`RC_ADMIN_TOKEN`，
> 独立于发给客户的中继令牌 `RC_TOKEN` —— 那条随主控端分发包发给客户了，不能当管理凭据），
> 别把带管理令牌的链接发给别人。

**方式二：命令行（服务器上）**

```bash
/opt/rcserver/rcctl status                       # 看状态、部署ID、剩余天数
/opt/rcserver/rcctl install "<激活码>"            # 安装/续期
```

**续期后不用做任何操作**：中继立即恢复；被控端/主控端最多 60 秒自动重连并恢复画面。

### 时间限制是怎么防绕过的

| 手段 | 说明 |
|---|---|
| 激活码签名 | 由厂商私钥签名：**改到期时间会验签失败**、**换台服务器无效**（绑定部署ID）、伪造的码中继直接拒收 |
| 服务器闸门 | 授权不可用时中继拒绝一切通信（WebSocket 握手、文件上传下载、在线列表全 403） |
| 客户端二次验签 | 被控端/主控端各自用内置公钥再验一遍：**即使有人改了服务器上的程序也拦得住** |
| **P2P 也要授权** | 关键：P2P 视频不经过服务器，所以被控端**本地也判一次**（见下） |
| 时钟回拨检测 | 把系统时间往回拨超过 6 小时会被判为异常并停机；服务器端同样检测 |

**"屏蔽中继域名/IP 就能白嫖 P2P"这条路是堵死的**：被控端把服务器下发的激活码缓存到本地
（`config\license.cache.json`），之后即使**完全连不上服务器**，也会在到期时刻自行停机 ——
停掉采集与编码（结束 Worker）、断开已接入的直连主控端、并**拒绝一切新的直连握手**
（回 `RC-DIRECT-DENY license`）。恢复联网并续期后自动重新可用。
实测（本机中继 + 真实被控端）：杀掉中继 → 到期时刻自动停机 → 直连握手被拒；
在管理页装好新激活码 → 47 秒后自动恢复画面。

- 查看本机缓存：被控端 `config\license.cache.json`（含激活码与"见过的最大时间"）
- 当前授权：`HK-REL-0001`，绑定部署 `DEP-F3F10F5ADF073CE3DC5D`，有效期至 **2027-09-20**


### 管理入口的令牌与"时间不倒退"（2026-09-22 修复）

**事故**：管理页 `/admin` 原先用**中继令牌**（`RC_TOKEN`）鉴权，而这条令牌随主控端分发包
（`viewer-defaults.txt` 的 `Token=`）发给了每个客户 —— 任何客户拿自己手里的令牌就能打开管理页：
恢复已撤销的激活码、把换下来的旧码（期限往往更长，如到期 2027 的旧码）重新装上，
盖掉新发的短有效期授权（"旧码到期 2027、新码到期 2026"的时间倒挂就是这么来的）。
修复两条，均已上服务器：

1. **管理令牌分离**：`/admin*`（含撤销名单同步 `/admin/revoked/sync`）只认
   `RC_ADMIN_TOKEN`（systemd 环境变量或 `-admin-token`，必须与 `RC_TOKEN` **不同**）。
   `RC_TOKEN` 继续用于 `/ws`、文件接口、`/api/agents` —— 客户端零改动。
   未配置 `RC_ADMIN_TOKEN` 的部署：`/admin` 仅限服务器本机访问
   （SSH 上去 `curl "http://127.0.0.1:8080/admin?token=<RC_TOKEN>"` 排障/续期），
   公网一律 401，启动日志会提醒配置。
2. **时间不倒退**：安装激活码时，若当前授权仍生效（`ok`），新码必须满足
   到期不早于当前授权、签发（iat）不早于当前授权 —— 换下来的旧码装不回去，
   授权也不能被无声缩短。真要回退/缩短：先显式撤销当前码，再装想要的码
   （撤销会让在线客户端立刻停机，所以必须是显式动作）。过期/已撤销状态下装码（自救）不受限。

管理令牌与中继令牌一样走 `?token=` / `X-RC-Token` / `Authorization: Bearer`；
厂商本机把它存到 `E:	ools\hk-admin-token.txt`（或私钥旁 `admin-token.txt`），
上位机会自动读取 —— 与中继令牌的查找顺序相同，管理令牌优先。


## 二、撤销（删除）激活码：让它立刻失效

场景：客户退款/欠费/停止服务，要**提前作废**一张还在有效期内的码。

在上位机的「激活码管理」页选中那条 →「**删除并失效**」。背后的链路：

| 环节 | 做了什么 |
|---|---|
| 上位机台账 | 标记为「已删除」，记下撤销时间与备注（默认列表里不再显示，勾「显示已删除」可回看） |
| 上位机 → 中继 | 把**激活码指纹**（sha256，不传码原文之外的东西）推给 `POST /admin/revoked/sync`（要令牌） |
| 中继 · 安装 | `Install()` 先查名单：命中直接拒绝，**粘贴多少次都装不回来** |
| 中继 · 复验 | 已装着的那条被撤销 → 状态立刻变 `revoked`，`/ws` 与所有业务接口一律 403 |
| 中继 · 在线客户端 | 状态跃迁时**主动推送** `{"type":"license","state":"revoked"}` 再断连 —— 只断连是不够的：被控端会退避重连，重连被拒后仍会拿本地缓存的旧码跑到期 |
| 被控端 | 收到 `revoked` → `LockFromServer` → 停机（停采集/杀 Worker/断已接入的直连/拒新握手）；**没连上的**由 60 秒一轮的 `/api/license` 探测补上 |
| 恢复 | 上位机「恢复」或 `/admin` 上的「恢复」→ 从名单移除（会带上 `remove` 同步）→ 该码可重新安装（只认管理令牌；重装同样受下文"时间不倒退"约束） |

**按指纹撤销，不按授权编号**：编号会被续期复用（`HK-REL-0001` 续期还是 `0001`），
按编号撤销会误伤同编号的新码；按码文本撤销只杀被删掉的那一条。
客户手里"能装得上"的码必然与撤销时那串完全一致（仅首尾空白会被归一）。

**两个必须知道的边界**：

1. 撤销要生效，前提是上位机能连上中继。台账里会区分「已删除（已失效）」与
   「**已删除（未同步！）**」—— 后者说明还没推上去，客户那边其实还能用到到期。
2. 被控端**长期离线**时，它只认激活码里的到期时间：要等它重新连上中继（60 秒一轮）才会停机。
   这与既有的"离线可用到到期"是同一个威胁模型，没有额外放宽。

撤销名单落在 `-data/revoked.json`（香港机器上是 `/var/lib/rcserver/revoked.json`），
随数据目录保留，升级二进制不影响；文件损坏时按空名单继续并记日志（不阻塞服务器启动）。


## 三、上位机（激活码生成器）与服务器入口

| 用途 | 位置 |
|---|---|
| 签发激活码 | `RemoteControl\build\tools\LicenseKeygen.exe`（图形界面：签发 / 台账管理 / 删除即失效；内置使用说明；也可 `--cli` 命令行签发） |
| 服务器安装/续期 | 浏览器 `http://202.60.232.209:8080/admin?token=<管理令牌>`（授权过期也能进），或 `rcctl install "<激活码>"` |
| 查看状态 | 同上页面，或 `rcctl status`，或 `/api/license` |
| 撤销名单 | 同上页面最下方「撤销名单（删除即失效）」；落盘 `-data/revoked.json` |

`E:\tools\hk-token.txt`、程序目录 依次查找，找到就填上并记住。

上位机命令行示例（脚本化签发）：
```
LicenseKeygen.exe --cli --lic HK-REL-0003 --sub "客户甲" --srv DEP-XXXX --days 365
```

## 四、离线宽限（"必须联网"策略）

**规则**：被控端**连续 48 小时联系不上中继**就停机（停采集/杀 Worker/断直连/拒新握手）；
一旦能连上，中继会下发当前激活码，被控端**自动恢复**，不需要人工干预。

为什么要有它：被控端本地只认激活码里的到期时间（这是为了"断网也能独立判到期"）。
副作用是——**把网线一拔、或者屏蔽中继只走 P2P，就能把一张已被撤销/已被改短的授权
一直用到它原来的到期时间**。宽限把这件事收敛到有界时间内：任何撤销或续期，
最多 48 小时一定生效。

| 配置项 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `MaxOfflineHours` | 被控端 `config\agent.json` | `48` | 多久联系不上服务器就停机；`0` = 不限制（旧行为） |

判定与恢复细节：

- **什么算"联系上"**：中继 WebSocket 连上，或 `/api/license` 探测成功（每 60 秒一轮）。
- **什么算"联系不上"**：两者都失败——注意这只影响**是否停机**，探测失败本身不会停机。
- **解锁条件**：只有"服务器下发的激活码本机复验通过"才解锁（`UpdateFromServer`）。
  也就是"能继续用"永远意味着"服务器刚刚确认过这张授权"。
- **重启不能重置宽限**：首次运行时间与最后联系时间都落在 `config\license.cache.json` 里，
  重启/重装程序文件都不会重新计时（除非删掉那个缓存文件，而删了它就没有可用激活码了）。
- **从没连上过的机器也算**：宽限从首次运行时刻起算，装好 48 小时内一次都没连上 → 停机。

对运营的含义：

1. 被控端机器必须**至少每 48 小时能连上一次中继**（正常联网的机器天然满足）。
2. 客户机器长期离线（比如搬走、断网）时被控端会停 —— 但那种状态下**本来也远程控制不了**
   （主控/被控都要经中继建立连接），所以不影响任何可用场景。
3. 想放宽/收紧：改被控端的 `MaxOfflineHours`（改完重启被控端生效）。特殊场景可以设 `0` 关掉。
4. **这条策略需要被控端是新版本**：老版本被控端没有宽限逻辑，得更新程序文件才生效
   （`scripts\deploy-quick.ps1` 或 `update-and-restart-agent.cmd`）。

## 五、主控端分发（零配置：地址与令牌随包预置）

主控端界面里**没有令牌输入框**（令牌是服务提供方的东西，不该让客户去填）。所以分发包必须在
打包时把**服务器地址与令牌**写进去：

```bash
python scripts\build-viewer-package.py        # 产物：build\主控端安装包.zip
```

脚本会：发布主控端到 `build\viewer\` → 写 `viewer-defaults.txt`（预置值取本机
`E:\RemoteControl\viewer\config\viewer.json` 的 `ServerUrl`/`AgentToken`，退回 `agent.json`）
→ 打包成 `build\主控端安装包.zip`（**不含** `config\`，客户各自生成）。

主控端启动时（`ViewerConfig.Load`）按这个优先级补齐配置：

| 情况 | 行为 |
|---|---|
| 本机还没有 `config\viewer.json`（客户第一次运行） | 预置值**直接生效**（否则会被代码里的占位默认 `127.0.0.1` 挡住） |
| 已有配置 | 只补**为空**的项，厂商/客户自己填过的值不动 |

`build-all.ps1` 也会在发布主控端后自动写一份 `build\viewer\viewer-defaults.txt`，
但它**不**打 zip —— 要发包请用上面那条命令。

排障：主控端报"未配置连接令牌 / 与服务端的连接令牌不一致"时，检查客户机器上主控端目录里
有没有 `viewer-defaults.txt`、里面的 `Token=` 是否与服务端 `RC_TOKEN` 一致（区分大小写）。

## 六、界面呈现约定（重要）
- **主控端不显示任何授权信息**：授权校验失败时只表现为"连不上/已断开"，原因写日志；
- **被控端不显示任何授权信息**：不弹托盘气泡、不改托盘提示、不向主控端上报原因，
  只在本地日志留一行中性记录（如"服务器校验未通过，暂停服务"）；
- 因此排查授权问题请走：服务器 `/admin` 页面 / `rcctl status` / 被控端日志 / 上位机验证框。


## 六、被控端开机自启（必须是"开机启动 + SYSTEM"）

**规则**：被控端在目标机器上注册的计划任务 `RemoteControlAgent` 必须是
**开机触发（AtStartup）+ 以 SYSTEM 运行 + 最高权限**。

为什么强调：早期安装脚本注册的是"**用户登录时**启动、并且绑定安装时那个用户"
（`-AtLogOn -User $domainUser -LogonType Interactive`）。被控机器经常停在登录界面、
或者重启后根本没人登录 —— 那样被控端**永远起不来**。实测踩到过：机器重启后数小时，
服务器上"没有在线被控端"，主控端列表一直是空的。

三重保障（新版本都有）：

| 位置 | 行为 |
|---|---|
| `install-agent.ps1` | 安装时注册 `RemoteControlAgent`：`-AtStartup` + `-UserId SYSTEM -LogonType ServiceAccount -RunLevel Highest` |
| **被控端自身**（`Program.EnsureBootAutostart`） | 启动时查一次任务，**不存在就自动补注册**（已存在则不动）—— 拷贝部署的机器、老版本装的机器，跑过一次就自愈。注意：它在**调试机**上也会生效（因为调试机跑的也是同一份程序） |
| `scripts\fix-agent-autostart.cmd` | 存量机器一次性修复：管理员运行 `fix-agent-autostart.cmd "D:\RemoteControl\agent"` |

排查"主控端看不到被控端"的顺序：

1. 服务器侧：`curl -H "X-RC-Token: <令牌>" http://<服务器>:8080/api/agents`；返回 `{"agents":[]}` 说明没有任何被控端连着
2. 被控端机器：任务计划里有没有 `RemoteControlAgent`（触发应为"启动时"、身份 SYSTEM）；没有就跑上面的修复脚本
3. 被控端日志：`<安装目录>\logs\coordinator-<日期>.log` —— 正常会写"已连接中继服务器 / 中继连接已建立 / 服务器授权校验通过"，异常也会写原因

## 七、上位机（签发 / 台账 / 撤销）—— 迁移自用户版说明书原第六章


上位机分三个页签：**签发激活码 / 激活码管理 / 使用说明**（内置使用说明就是完整版手册，直接在程序里看）。

### 签发

填授权编号、客户、绑定部署ID（默认已从服务器自动读好）、有效期 → 点「生成激活码」→
再点「**安装到服务器**」（「中继令牌」可留空，程序会自动读取；省掉复制粘到浏览器那一步）。
也可以复制激活码，到 `http://<服务器>:8080/admin?token=<管理令牌>` 粘贴安装（或服务器上
`/opt/rcserver/rcctl install "<码>"`）。装好后被控端/主控端 **60 秒内自动重连**，不用人工重启。

> 有效期按 **UTC** 解释（界面上的「生效日期（UTC）/到期日期（UTC）」），
> 和中继 `/admin`、被控端日志、服务器判定保持一致，不会再出现差 8 小时。
> 到期日当天仍然有效。

### 台账（发过哪些码、哪些在用）

每签一条自动记进**私钥旁边的** `license-history.json`（跟着私钥备份即可，换台机器也是同一本账）：

| 状态 | 含义 |
|---|---|
| **使用中** | 服务器上装的就是这一条（按激活码指纹与服务器精确比对，不是猜的） |
| 曾使用（已换码） | 以前装过，现在服务器上换成了别的码（续期了） |
| 未使用 / 已过期 | — |
| **已删除（已失效）** | 被删掉的码：客户那边会停机，且装不回来 |

「刷新服务器状态」会顺带把「使用中」标出来；「导出 CSV」可把整本台账导成表格（Excel 直接打开）。

### 删除一条激活码 = 让它彻底失效

选中一行 →「删除并失效」。中继会把它放进**撤销名单**，并且：

- **正在装着的**：立即判 `revoked`，拒绝一切通信，并主动通知在线被控端停机（含 P2P 直连）；
- **想重新装回来的**：安装接口直接拒绝，粘多少次都没用；
- 撤销按**激活码原文**记，所以给同一客户**新签发**的码不受影响（续期照常）。

名单可以在服务器 `/admin` 页面上看和改（也有「恢复」按钮撤销删除）。
`/var/lib/rcserver/revoked.json` 会随 `-data` 目录保留，升级二进制不影响。

**两点必须知道**：

1. 删除要生效，前提是上位机能连上中继；状态列会区分「已删除（已失效）」与
   「**已删除（未同步！）**」，后者说明客户那边其实还能用到到期 —— 点「同步撤销名单」补推即可。
