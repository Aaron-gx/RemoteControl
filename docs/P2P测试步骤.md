# P2P 直连：怎么测（两台不同网络的电脑）

## 一、先理解现在的连接方式

```
主控端(你的电脑) ──┐
                  ├── 中继(香港 202.60.232.209:8080)：信令 + 控制/输入/剪贴板 + 兜底
被控端(别人电脑) ──┘
                  └── P2P 直连（可选）：**视频**走点对点，不经香港
```

为什么这样分工：视频占 95% 以上带宽，走直连收益最大；控制/输入/剪贴板只有 KB 级，
留在中继上更稳（而且中继本来就在，用于信令与失败兜底）。

**直连尝试顺序**：UPnP 映射出来的公网地址 → 内网 IP（同局域网时最快）→ 都不行就用中继。
**全程自动**，断了会自动回到中继，不用手动切。

## 二、测试前：确认被控端有直连能力

在被控端电脑上：

1. 以**管理员**重启被控端（快捷方式「远程控制-被控端」或双击
   `E:\RemoteControl\agent\Agent.Coordinator.exe`，UAC 点「是」）
2. 看被控端日志 `E:\RemoteControl\agent\logs\coordinator-*.log`，应出现：
   ```
   P2P 直连监听已启动：0.0.0.0:47890（内网候选 192.168.x.x:47890）
   P2P 公网候选：x.x.x.x:47890（主控端可直连）        ← UPnP 成功才有这行
   ```
   - 有「P2P 公网候选」→ 跨网也能直连 ✅
   - 只有「内网候选」+ 「UPnP 不可用」→ 跨网走中继（局域网内仍可直连）。
     想让跨网直连生效，二选一：
     * 在路由器上打开 **UPnP**（推荐，多数家用路由器有）
     * 或手动把 **TCP 47890** 端口映射到被控端内网 IP，然后在被控端 `agent.json` 里填
       `"DirectLinkPublicAddress": "你的公网IP:47890"`

## 三、测试步骤（两台不同网络）

### 1) 第二台电脑装主控端（控制第一台）
1. 把 `E:\RemoteControl\viewer` 整个目录拷到第二台电脑（U 盘/网盘/共享都行）
2. 编辑 `viewer\config\viewer.json`：
   ```json
   {
     "ServerUrl":     "ws://202.60.232.209:8080/ws",
     "FileServerUrl": "http://202.60.232.209:8080",
     "AgentToken":    "<与被控端相同的令牌>",
     "TargetAgentId": "AURA-D7F4CA42",
     "AutoConnect":   true
   }
   ```
3. 双击 `Viewer.exe` → 状态栏变绿即已连接

### 2) 看是不是直连
主控端状态栏右侧会显示 **`连接: 直连`** 或 **`连接: 中继`**：

| 显示 | 含义 |
|---|---|
| `连接: 直连` | 视频**没经过**香港，点对点传输；连接栏会显示 `P2P 直连成功：<地址>` |
| `连接: 中继` | 走了香港（对端没有可达公网地址），功能完全一样，只是延迟略高 |

被控端日志同步可查：
```
P2P 直连：收到来自 x.x.x.x:xxxxx 的连接，等待握手…
P2P 直连已建立：x.x.x.x:xxxxx（视频改走直连，控制仍走中继）
[诊断] … 直连=已建立(x.x.x.x:xxxxx, 1234帧/5678KB)
```

### 3) 反过来测（用第一台控制第二台）
在第二台电脑上布署被控端（需要管理员跑一次安装脚本，见
`docs\部署-香港服务器.md` 与 `README.md` 的「被控端」章节），第一台用 Viewer 连它的 AgentId。

## 四、自动化验收（不用两台机器也能跑）

单机上就能验证「直连链路成立 + 视频确实走了直连」：

```powershell
# 在被控端所在机器上（会连到本机的中继/被控端，直连候选是本机内网地址）
E:\...\RemoteControl\build\tests\E2E.exe `
  --server ws://202.60.232.209:8080/ws --agent <AgentId> --token <令牌> `
  --dir E:\RemoteControl\e2e --ffmpeg <repo>\third_party\ffmpeg\ffmpeg.exe --scenario direct
```
断言内容（关键就是「中继侧视频已停」这条 —— 中继不再收到视频才叫 P2P 成立）：
```
[PASS] 中继链路已收到视频（对照组）
[PASS] 被控端上报了直连候选
[PASS] P2P 直连建立成功
[PASS] 被控端确认视频已改走直连            ← 被控端上报的直连帧数在增长
[PASS] 被控端确认中继侧视频已停（P2P 成立的关键证据）  ← 被控端上报的中继块数「一块都没再涨」
[PASS] 视频经直连传输
[PASS] 中继侧视频已停止（含在途残帧排空）   ← 主控端侧实测（2 秒一段，直连 ≥10 倍于中继）
[PASS] 直连期间画面仍在解码
```
说明：断言分两层证据 ——
- **被控端侧**（确定性）：被控端把自己"视频到底发给谁"的计数放进状态上报
  （`directFrames` / `relayChunks`），直连生效后 `relayChunks` 必须**停止增长**，
  不受网络在途残帧影响。
- **主控端侧**（观察）：允许一段排空时间（前面的场景可能在中继排队里积了旧码流），
  只要出现一段 2 秒窗口里「中继 < 直连的 1/10」即判定中继已停。

独立旁证（不看软件自己的计数，最硬）：直连生效时在香港服务器上采样网卡，视频流量应当消失：
```bash
# 服务器上（ens17 是网卡名）
for i in $(seq 1 30); do echo "$(date +%s) $(cat /sys/class/net/ens17/statistics/rx_bytes)"; sleep 1; done
```
实测：中继转发视频时 RX 约 80~500KB/s，**P2P 生效那几秒掉到 0.5~0.9KB/s**，直连断开后又回到 250~500KB/s。

## 五、常见问题

| 现象 | 处理 |
|---|---|
| 一直显示「连接: 中继」 | 对端没有可达的公网地址：开路由器 UPnP，或手动映射 47890 并填 `DirectLinkPublicAddress` |
| 显示「P2P 直连不可用」 | 同上；不影响使用（自动用中继） |
| 直连成功一会儿又变中继 | 直连链路断了（网络切换/NAT 超时），已自动回落，属预期行为 |
| 想看是否真的省了服务器带宽 | 服务器上 `vnstat -l` 或 `iftop`，直连生效时看不到视频流量 |
| 端口 47890 冲突 | 被控端 `agent.json` 里改 `DirectLinkPort`，并同步做端口映射 |
