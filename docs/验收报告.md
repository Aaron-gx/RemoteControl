## 六、实现过程中定位并修复的关键缺陷（均为真机复现 → 修复 → 复测通过）

1. **跨会话共享内存/命名管道被"强制完整性标签"拦截**
   管理员进程（High IL）创建的对象带 High 标签，普通用户（Medium）即使 DACL 有权限也打不开。
   修复：安全描述符加 `S:(ML;;NW;;;LW)` 并启用 `SeSecurityPrivilege`；无特权时自动降级并告警。

2. **`CreateFileMappingW/OpenFileMappingW` 缺少 `CharSet.Unicode`**
   默认 Ansi 导致对象名被搞乱并落入"会话命名空间"：单会话正常、跨会话报"找不到文件"（Win32=2）。

3. **`TOKEN_PRIVILEGES` 结构体内存布局错误**（`long` 的 8 字节对齐导致整结构 24 字节）
   → 所有特权启用都返回 `ERROR_NOT_ALL_ASSIGNED`，`CreateProcessAsUser` 永远失败。
   修复后 `SeDebugPrivilege`/`SeIncreaseQuotaPrivilege` 正常启用。

4. **复制会话进程令牌时进程句柄权限不足**：`OpenProcessToken(TOKEN_DUPLICATE)` 需要
   `PROCESS_QUERY_INFORMATION`，仅给 `QUERY_LIMITED` 会被拒（ACCESS_DENIED）。

5. **主控端活跃判定错误**：中继是透传的，Agent 不能以"自己连上服务器"判断主控端在场；
   且心跳消息在客户端被提前 `return`，导致 6 秒后误判"无主控端"而停发视频。改为"最近 6 秒有入站消息"。

6. **实时视频管线阻塞网络接收循环** → 中继因写超时踢连接。
   改为非阻塞入队 + 积压丢块 + 双向 `StreamReset` 重建编解码器（丢块后必须等新 IDR）。

7. **RDP 会话"已断开"时无显示表面**：会话内 GDI/WGC/DD 全部失败；
   且对断开会话直接重连会卡在会话内登录界面 → 实现"观察窗口 + 注销重建"状态机。

8. **RDP 客户端窗口最小化会使会话进入"无显示"状态**（光标恒 0,0、无前台窗口，注入失效）
   → 改为连接后 `SW_HIDE` 隐藏（恰好实现策划要求的"连上后自动隐藏"）。

9. **控制台程序主窗口句柄为 0**（窗口属于 conhost.exe）→ 用 `AttachConsole+GetConsoleWindow` 定位，
   并加"ALT 解锁 + AttachThreadInput"提高置前台成功率，键鼠注入才真正落到目标窗口。

10. **建立会话过快重试导致永远建不成**（首次登录建配置文件需 40~60s）→ 观察窗口 + 最多一次重试。

11. **虚拟显示器识别靠"猜设备名"不成立**：VDD 的显示器设备名是 `\.\DISPLAYxx` 且每次重载都会变号，猜名字永远识别不到。改为用 `EnumDisplayDevices(NULL, i, …)` 枚举**适配器**取适配器名（"Virtual Display Driver"）判定；随后驱动默认的 800×600 桌面模式也被自动切到 1920×1080：

    ```
    17:34:59 切换 \.\DISPLAY56：800x600@60 → 1920x1080@60
    17:34:59 \.\DISPLAY56 已切换到 1920x1080@60
    虚拟副屏：驱动已安装 / 虚拟屏已生效 / 当前显示：
      \.\DISPLAY1 1920x1080@(0,0) [主] <AMD Radeon(TM) Graphics>;
      \.\DISPLAY2 1920x1080@(-1920,0) <AMD Radeon(TM) Graphics>;
      \.\DISPLAY56 1920x1080@(1920,0) <Virtual Display Driver>
    ```

    注意 `EnumDisplayDevices(显示器名, 0, …)` 只会返回 "Generic PnP Monitor"（子设备），必须传 NULL 枚举适配器。

## 七、已知限制与建议

| 项 | 说明 |
|----|------|
| RDPWrap 依赖系统版本 | 系统更新更换 `termsrv.dll` 后需更新 `rdpwrap.ini`；安装脚本已做版本核对并给出提示 |
| 虚拟副屏与 RDP 会话的关系 | 实测 VDD 显示器挂在 **console 会话**，Agent 启动时已自动把驱动默认的 800×600 切成 **1920×1080@60**（适配器名 "Virtual Display Driver"，设备名 `\.\DISPLAYxx` 会随重载变号）；RDP 会话使用自己的虚拟显示（`\.\DISPLAY1`，1920×1080）。策划中"每个 RDP 会话各挂一块虚拟屏"的组合在 24H2 上不成立，本实现按"RDP 会话自带虚拟显示 + VDD 为 console 会话提供 1920×1080 虚拟副屏"落地，两项功能目标均达成 |
| 硬件编码 | 本机 GPU（AMD RX 550X）未提供可用 AMF H.264，实测自动回退 `libx264`；在有 NVENC/QSV 的机器上会自动选用硬件编码（1080p30 约 20~40fps，CPU 占用更低） |
| 1080p30 的解码开销 | 主控端解码为 CPU 软解（ffmpeg），占单核约 60~80%；如需更低占用建议换用硬解 |
| 托盘"退出"菜单 | 未做自动化点击验证（需人工点一次即可确认） |
| `go test -race` | 本机无 C 编译器且 TSan 与地址空间不兼容，未能执行；已用 28 项并发相关用例替代（含并发压力用例） |

## 十、激活码（时间限制）机制

**设计（对抗"用 AI 反编译后打补丁/伪造激活码"）**

| 手段 | 说明 |
|---|---|
| **非对称签名（核心）** | 激活码由厂商私钥（上位机）签发，中继与客户端里**只有公钥**。私钥从不出现在任何交付物中 → 即使完全反编译，也**无法伪造**激活码，只能去改校验代码本身 |
| 时间窗写进签名 | 到期时间在签名保护范围内，改大 → 验签失败（实测：篡改后状态 `invalid`、通信 403） |
| 部署绑定 | 激活码绑定"部署ID"（首次运行生成），换台服务器无效（实测：装不上，报绑定不符） |
| 时钟回拨检测 | 落盘"见过的最大时间"，时间倒退超过 6 小时即锁定，防"把系统时间调回去继续用" |
| **客户端二次校验** | 中继把授权状态**与原始激活码**一起推给被控端/主控端，两端各自用内置公钥再验一次 → **只改中继二进制也不够**，还得改客户端；授权失效时两端都主动停止并提示 |
| 失败即锁 | 授权文件缺失/损坏/读不出 → 一律按未授权处理，绝不默认放行 |
| 到期即时生效 | 请求路径上当场比对时间窗（不等 30 秒复验周期），并会断开已建立的连接 |
| 防暴力/防批量 | 激活码为 256 位 ECDSA 签名（不可穷举）；安装失败有明确原因与日志 |

## 十四、第三阶段：P2P 实装 + 黑屏根因修复（真机验收）

### 14.1 黑屏根因（真机定位）

现象：主控端能连上、能看到软件列表，但画面全黑。
排查：`query session` 只有 console；没有 `Agent.Worker` 进程；`TerminalServices-RemoteConnectionManager`
事件日志里自 22:01 起再无"侦听程序 RDP-Tcp 已收到一个连接"。

**根因**：Windows 11 24H2 起，`.rdp` 文件里内嵌密码会让 mstsc 弹出一个**阻塞式**安全警告
（标题「远程桌面连接安全警告」，内容「此远程连接可能会损害本地或远程计算机…无法验证此远程连接的发布者…
使用以下凭据连接: RemoteWorker 的密码」，按钮「连接(N)/取消(C)」）。
无人值守时没人点它 → mstsc 永远停在对话框上 → 180 秒超时 → 没有 RDP 会话 → 没有 Worker → 黑屏。
（同一现象在旧版 Windows 上是证书警告「无法验证此远程计算机的身份」，按钮「是(Y)/否(N)」。）

**修复**（四处真实缺陷，均为真机复现 → 修复 → 复测）：

1. `RdpSessionManager.DismissBlockingDialogs()`：每 2 秒扫描**仅属于 mstsc 进程**的对话框，
   勾上"不再询问"类复选框后点确认按钮（`连接/是/确定/重试/Yes/Connect…`，**绝不点取消/否**）；
   建立会话的等待循环与 20 秒看护都会调用它。
2. 看护重建会话后，会话 id 没回传给协调器 → `LaunchWorker` 一直打印「尚未确定 Worker 会话」，
   Worker 永远起不来。现在 `RdpSessionManager.WorkerSessionId` 会回填。
3. **会话号会变**（每次重建 +1：2 → 3 → 4 → 5），只"回填一次"仍然会拿旧会话号去启动 Worker
   → 改为**只要发现会话号和记录不一致就刷新**；同时把看护的"3 分钟宽限期"改成
   "会话确实还在才等"（会话消失必须尽快重建，实测重建从 3 分钟缩短到 20 秒内）。
4. 键鼠注入偶发失效：控制台窗口还没"长成"正常尺寸时被枚举到（`conhost 控制台窗口 XX 尺寸退化(16x16)`）
   → 判定失败 → 没有前台窗口 → **按键全部丢失**（日志 `当前没有前台窗口（fg=0）`）。
   现在：等待窗口成形的重试从 5 秒延长到 8 秒；控制台类窗口同时识别
   `ConsoleWindowClass` 与 Windows 11 默认终端 `CASCADIA_HOSTING_WINDOW_CLASS`；
   实在只有退化/未显示的窗口，也**必须**给它前台（窗口小不影响按键进入它的控制台输入缓冲）。

**验证**：手动注销 Worker 会话 + 杀掉 mstsc（模拟掉线），连续两次实测：

```
23:39:04 打掉会话（mstsc 被杀 + 会话注销）
23:39:2x 检测到 RDP 会话不可用，执行自动重建 → 已启动 mstsc
23:39:2x 已自动确认 mstsc 对话框：「远程桌面连接安全警告」→ 继续连接   ← 无人值守关键一步
23:39:25 RemoteWorker 会话已就绪且活动：id=5（用时 4.1s）             ← 原来是 180s 超时
23:39:25 Worker 已启动：session=5 pid=15676 方式=schtasks
23:39:25 Worker 就绪：WGC 1920x1080 monitor=\\.\DISPLAY1 session=5
23:40:09 [诊断] 转发帧 206/5s  主控端=无                              ← 画面已自行恢复
```
全程 **21 秒、无需任何人工点击**。

### 15.3 P2P 防绕过（本轮重点）

问题：时间限制原本只在服务器上判定，而 P2P 直连的视频**不经过服务器** ——
只要屏蔽中继地址，是不是就能一直白嫖直连？

现在被控端本地加了 `LicenseGate`（`Agent.Common/LicenseGate.cs`）：

| 机制 | 行为 |
|---|---|
| 本地缓存 | 服务器下发的激活码在本机用内置公钥**再验一次**后缓存到 `config\license.cache.json` |
| 本地到期判定 | 缓存里的到期时间到了 → **不依赖任何网络**直接停机（每 60 秒判一次） |
| 时钟回拨检测 | 见过的最大时间比现在晚超过 6 小时 → 判为改时间 → 停机 |
| 缓存被改 | 启动/每轮复验发现验签失败 → 停机 |
| 硬停机动作 | 结束 Worker（不采集不编码）+ 断开已接入的直连主控端 + **拒绝新的直连握手**（回 `RC-DIRECT-DENY license`）+ 不再转发任何帧 |
| 自动恢复 | 停机期间每 60 秒重试连接中继；服务器装好新激活码后**无需重启**自动恢复 |

主控端同步加固：**中继一断就停掉直连**（不再出现"中继断了画面还在走 P2P"）。

控制/剪贴板/文件/软件列表**始终走中继**（信令与兜底通道）。

切回「自动」后直连恢复（日志 `P2P 直连已启用`）。证据：`docs/evidence/界面-仅中继模式.png`。

### 16.4 激活码到期时间随处可见

- 被控端把本地授权闸门的信息（编号/客户/到期/剩余/是否已停机）放进每秒的状态上报；
- **主控端状态栏直接显示** `授权: 有效至 2027-09-22（剩余 366 天）`，**点开**有详情弹窗
  （编号、客户、到期时间、被控端是否已停机及原因、服务器续期入口 URL）；
- 剩余 ≤30 天自动加 ⚠ 前缀。

顺带修掉一个真实异常：状态栏刷新时 `DateTime.MinValue` 隐式转 `DateTimeOffset`
在 UTC+8 会抛 `ArgumentOutOfRangeException`（被控端状态里的到期字段为空时触发）；
另外直连模式下码率一直显示 0（直连字节没计入统计）也已修复。

### 16.5 顺带修掉的真实缺陷：多主控端时视频被直连"独占"

把主控端开着再跑 E2E 时发现：E2E 作为第二个主控端**一个字节视频都收不到**。
原因：被控端的视频出口在直连生效时**只走直连**，而直连只服务一个主控端 →
中继上的其他主控端全黑屏（此前文档写的"其余走中继"是错的）。

修复：中继在**主控端接入/断开时推送当前数量**（`{"type":"viewers","count":N}`），
被控端据此决定路由 —— **多于一个主控端时统一走中继并停掉直连**（人人有画面），
只剩一个主控端时恢复 P2P 直连。新增 Go 测试 `TestRelayPushesViewerCountToAgent`。

> 注：该修复需要中继更新后才能在香港服务器生效（见 15.5 的 SSH 限制）。

### 18.4 已知限制（本轮实测发现）

- **同一被控端同时接入多个主控端时**：旧版中继不会告知被控端"有几个主控端"，被控端会把视频
  只发给直连那一路，中继那一路的发送队列可能积压（实测一次性积压 512 条 ≈ 8MB），
  控制/状态消息会被压在视频后面延迟送达（表现为"状态上报晚到"）。
  新版中继已加"主控端数量"推送（多于一个时全体走中继，见 16.5），待部署到香港后该现象消失；
  单主控端场景不受影响（30+ 次全量 E2E 均为绿色）。
- 后续可再做一层保险：中继侧发送队列设置上限，超限时**丢最旧的视频帧**而不是无限排队
  （控制消息永不丢弃），把积压延迟压到秒级以内。

### 18.5 装完自动告诉你"连没连上服务器"（用户反馈后补）

现象：用户用安装程序在异地电脑上装了被控端，但主控端列表里看不到那台电脑 —— 因为
**装好了但连不上服务器**，而原来的安装程序装完就结束了，不给任何连通性结论。

改进（已实测）：

1. **装完立刻做连通性自检**：安装程序自动调用安装包里的 `连接自检.ps1 -NoPause`，
   把 配置→地址→端口→健康检查→令牌→在线列表→WebSocket 握手 的结果直接印在日志区，并弹出结论：
   - 能连上 → “安装完成，已连上服务器。这台电脑的 AgentId = AURA-XXXXXXXX，主控端刷新后选它即可连接”
   - 连不上 → 明确写出失败项 + 常见原因（网络被挡 / 令牌不对 / 服务器不可用）与处理办法
2. **被控端托盘图标显示连接状态**：`已连接服务器` / `未连接服务器（会自动重试）`，
   用户悬停托盘即可判断，不用翻日志。
3. **`连接自检.cmd` 随安装包分发**（也放进被控端/主控端目录），任何时候双击即可复检。

实测截图：`docs/evidence/界面-安装完成已连上服务器.png`（安装程序弹出“已连上服务器 + AgentId”）。

### 18.6 事故记录：部署脚本误删 ffmpeg 导致"Worker 起来就死、画面 0 帧"

现象：本机被控端画面停在 0 帧（主控端黑屏），日志里每 ~25 秒出现一轮
`Worker 已连接 Named Pipe` → 4~5 秒后 `IPC 读取循环结束` → `Worker 收尾完成（采集 0 帧）`，
Worker 反复"起来就死"。

排查：把 Worker 日志级别调到 Debug 后仍然没有退出原因；关键线索是**日志里缺了 `ffmpeg：<path>` 这一行**
（正常启动顺序：采集源就绪 → `ffmpeg：...` → `自动选择编码器` → `启动 ffmpeg`）。

根因（连锁）：`build\agent` 里原本被 build-all.ps1 额外拷入的 `third_party`（含 ffmpeg）与 `drivers`
在某次构建清理中丢失；而 `scripts\deploy-quick.ps1` 用 `robocopy /MIR` 从 `build\agent` 同步到运行目录，
**/MIR 会把运行目录里"源端没有"的文件删掉** → 运行目录的 `third_party\ffmpeg\ffmpeg.exe` 被删除 →
Worker 启动时 `ResolveFfmpeg()` 抛 FileNotFoundException（位于 `Start()` 里，异常经 `using` 析构打印
"收尾完成"后进程退出）→ 表现成"起来就死、0 帧"。

修复（三处，均已实测）：

1. `deploy-quick.ps1` 的 `/MIR` 排除 `third_party`、`drivers`、`docs`、`config`、`logs` —— 不再可能删除运行期资源；
2. 把 ffmpeg 与驱动补回 `build\agent`（并在打包脚本里固定从仓库正规来源补齐）；
3. Worker 在找不到 ffmpeg 时**不再抛异常**，改为打印明确错误并走"编码器启动失败"的正常收尾路径
   （避免以后再出现"静默退出、无原因"的难查现象）。

验证：修复后 `转发帧 204~215/5s`、Worker/ffmpeg 稳定运行、主控端 P2P 直连出画面（软件列表 54 项）。

## 十九、第八阶段：安装程序改为"单文件 + 零填写"，被控端主动上报

用户反馈三条：① 安装程序要一个 exe（而不是一堆文件）；② 界面要像正常安装软件（不要深色"乌漆抹黑"）；
③ 被控端不该填任何参数（口令只属于主控端），并且被控端应**主动向服务器上报自己**，还抱怨"每次都搜不到"。

### 19.1 已整改（本轮）

| 项目 | 之前 | 现在 |
|---|---|---|
| 分发形态 | 安装程序 + payload 目录（约 350MB 一堆文件） | **一个 `被控端安装程序.exe`（201MB）**，payload 以 zip 内嵌，运行时解到临时目录 |
| 界面风格 | 深色主题 | **标准浅色安装界面**（白色背景、常规按钮、大号「开始安装」） |
| 要填的参数 | 服务器 + 连接口令 + 目录 + 4 个选项 | **零必填**：服务器地址与口令打包时写入，收在默认折叠的「高级设置」里；选项均有默认值 |
| 装完结果 | 只说"完成" | **装完自动连通性自检**：直接显示"已连上服务器 + 这台电脑的 AgentId"或"连不上 + 原因" |
| 被控端上报 | 只有 AgentId | **主动上报计算机名/用户名/系统版本/程序版本**；主控端状态栏显示"哪台电脑" |
| 连不上时 | 固定一个地址反复失败 | **多端点自动重试**：主地址 → 配置的备用 → 同主机 **443 / 8443**，谁先通用谁（网络封 8080 时可自动改道） |

### 19.2 关于"口令"（AgentToken）

口令是两端与中继之间的共享凭据（服务器据此判断连接是否被允许）。按用户要求调整为：
**口令只属于主控端与中继**，被控端安装包内预置、用户不接触、不填写；主控端侧仍用它连中继。

### 19.3 仍需服务器侧配合的一件事（我这边 SSH 被拦）

要让"网络封了 8080 的机器"也能连上，需要在服务器上让中继**同时监听 443/8443**
（80/443 是几乎不会被封的端口）。当前实测：服务器 22 端口 TCP 可连但 SSH 握手被拦、80/443 未开放、8080 正常。

需在服务器执行（任选其一）：
```bash
# 方案 A：再开一个监听端口（新版中继支持多个 -addr）
systemctl edit rcserver        # 在 ExecStart 后追加：-addr :8080 -addr :443
systemctl restart rcserver
# 方案 B：把主端口直接改成 443（两端地址同步改成 ws://202.60.232.209:443/ws）
```
被控端已经会自动尝试 443，无需改任何配置即可生效。

### 19.4 安装界面重做（按反馈：颜色不统一 / 不像正常安装程序）

第一版浅色界面被指出"颜色配不齐、日志区字看不清、按钮发灰"。重做为**标准安装向导**
（与 QQ/腾讯等安装包一致的四步式）：

1. **欢迎**（蓝色品牌条 + 会做什么的清单）→「下一步」
2. **选择安装位置**（目录 + 浏览…，服务器/口令/选项收进默认折叠的「高级设置」）→「开始安装」
3. **正在安装**（进度条 + 白底深字日志区 + 状态行）
4. **安装完成**（✓ 结果 + **这台电脑的 AgentId** + 计算机名 + 「完成后自动启动被控端」勾选）→「完成」

配色统一为：品牌蓝 `#1E7BE4`、正文 `#1F1F1F`、次要文字 `#6B6B6B`、分隔线 `#E6E6E6`、
输入框 `#FBFBFB`；主/次按钮各自一套模板（含 hover 与禁用态），不再出现"发灰看不清"。

**安装选项说明（回答"不勾是不是就没法用"）**：三项必要功能**默认全部勾选**，正常用户完全不用碰：
- 多会话支持：不勾 → 远程操作会与本机使用抢同一块桌面（互相干扰）；
- 开机自启动：不勾 → 重启后不会自动上线，主控端连不上；
- Defender 排除项：不勾 → 可能被误杀。
虚拟副屏默认不勾（仅没有显示器的机器才需要）。这些都在「高级设置」里，界面默认是简洁的四步向导。

**本轮同时修掉两个真 bug**（都在自检截图时发现）：
1. 向导第 1 页点「下一步」会**直接开始安装**（应只进入第二页）→ 已修；
2. 安装程序会**开出两个窗口**（App 与 Program 各创建一次）→ 已修（预览参数也因此失效）。

## 二十、第九阶段：服务器多端口监听（443/8443）· 客户端端口回退落地

背景：部分网络封 8080。客户端早已内置"主地址 → 同主机 443 → 8443"的候选重试
（`RelayClient.cs:85-86`），但服务端只有 8080 一个监听，回退无处可去。

### 19.1 服务端改造

- `-addr` 由 `flag.String` 改为 `flag.Func` 收集（**可重复**：`-addr :8080 -addr :443 -addr :8443`），
  不带则默认 `:8080`（老命令、rcctl、测试全部兼容）
- `run()` 拆为 `runAddrs([]string, ...)`（`run` 保留为单地址包装，既有测试不动）
- **容错**：各端口独立 `net.Listen`，失败只记 `warning` 不中断；全失败才返回错误
  （避免"443 被占用把 8080 一起拖down"这种远程改配置最怕的事故）

## 二十一、第十阶段：离线宽限（"必须联网"策略）

背景：被控端本地只认激活码里的 exp（为了断网也能独立判到期）。副作用是"拔网线/屏蔽中继走 P2P"
就能把旧授权一直用到旧到期时间 —— 厂商提出的场景是"新码有效期比旧码短，旧码仍可能被继续使用"。

### 21.1 实现

| 位置 | 改动 |
|---|---|
| `AppConfig` | 新增 `MaxOfflineHours`（默认 **48**，`0` = 不限制 = 旧行为）与 `MaxOffline` |
| `LicenseGate` | 新增离线宽限判定（放在 `Tick` 最前面，连"从没拿到过激活码"的机器也管）；新增 `NoteServerContact()`；缓存新增 `ContactUnix`/`FirstRunUnix` 并落盘 |
| `LicenseGate` 缓存 | 没有缓存文件时也会先写一次（把首次运行时刻落盘）；`Save()` 不再因"还没有激活码"而跳过 —— 否则重启就能重置宽限 |
| `Program`（Coordinator） | 中继连上（`OnRelayConnected`）与 `/api/license` 探测成功都调 `NoteServerContact()`；按配置传入宽限 |

判定与恢复：**联系上** = 中继 WS 连上 或 探测成功；**解锁**只由"服务器下发激活码复验通过"触发
（`UpdateFromServer`），保证"能继续用"永远意味着"服务器刚确认过授权"。停机动作复用既有 `LockDown`
（停采集 / 杀 Worker / 断直连 / 拒新握手），联网后 60 秒内自动恢复。

### 21.2 验证

| 项目 | 结果 |
|---|---|
| C# 单元测试 | ✅ **75/75**（新增 6 项：离线超限启动即判停 + 重新联系后仅"联系"不解锁、服务器下发激活码才恢复 / 宽限内不停机 / `0` 时不启用（向后兼容）/ 从没联系过按首次运行起算 / **首次运行时间落盘且重启不重置** / 联系成功会刷新落盘时间） |
| 被控端构建 | ✅ `build\agent` 已更新（含宽限逻辑） |
| 安装包 | ✅ 重新打包（新装的机器直接带宽限策略） |

### 21.3 边界与运营

- 被控端机器需**至少每 48 小时能连上一次中继**；正常联网的机器天然满足。
- 客户机器长期离线时被控端会停 —— 但那种状态下本来就远程控制不了（连接必须经中继建立），
  不影响任何可用场景，且**联网后自动恢复**，不需要人工处理。
- **老版本被控端没有这条逻辑**，要更新程序文件才生效（`scripts\deploy-quick.ps1` / `update-and-restart-agent.cmd`）。

## 二十四、第十三阶段：授权管理入口越权修复（客户令牌可恢复已撤销激活码）

**触发（2026-09-22 用户报告）**：浏览器里 `http://202.60.232.209:8080/admin?msg=已恢复（重新安装该激活码即可生效）&token=KFZzxMEo…`
—— 质疑两点：①为什么"恢复"能成功；②旧密钥到期 2027-09-20（HK-REL-0001），新密钥到期
2026-10-21（HK-REL-0006），恢复/重装旧码等于把授权时间改回去，"违反了时间"。

### 24.1 根因（两处叠加）

| # | 问题 | 证据 |
|---|---|---|
| 1 | **管理入口用的是"客户手里就有的"令牌**：`/admin*` 的鉴权 = 中继令牌（`RC_TOKEN`），而同一条令牌随主控端分发包（`viewer-defaults.txt` 的 `Token=`）与被控端配置发给每个客户 → 任何客户都能打开管理页：恢复已撤销的码、重装旧码盖掉新码、卸载授权 | `build/viewer/viewer-defaults.txt` 的 `Token=` 与 systemd `RC_TOKEN` 逐字节相同 |

### 24.2 修复（两道闸 + 打包卫生）

1. **管理令牌分离（服务器）**：新增 `-admin-token` / `RC_ADMIN_TOKEN`；`/admin*`（含
   `revoked/sync`）只认它，`?token=` / `X-RC-Token` / `Bearer` 三种传法一致。
