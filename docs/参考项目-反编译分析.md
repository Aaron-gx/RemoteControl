## 2. 被控端 `agent.pyc` 的思路（总共 3 个顶层对象）

```
detect_monitors()      枚举显示器 → (物理编号, 虚拟编号)
FreezeWindow           盖在物理屏上的"冻结画面"窗口
ControlledClient       连接、截屏发帧、应用远端事件
```

- **显示器**：`detect_monitors()` 枚举所有显示器并要求**至少两块**，自动挑出"物理屏"和"虚拟屏"，
  也可用命令行参数指定；只有一块屏时直接退出并提示
  **"请至少连接一个虚拟显示器（如 usbmmidd）"**。
  → 它**不创建**虚拟显示器，只用已经装好的那块。
- **传输**：裸 TCP（无 WebSocket / 无 TLS / 无中继）。协议是
  `send_msg(msg_type, data)` = **`[4 字节大端长度][载荷]`**，
  载荷是文本，`msg_type` 就是 `"move"` / `"click"` / `"freeze"` 这类字符串，字段用 `,` 分隔。
- **画面**：`send_frames_loop` **只截虚拟那块屏**：
  `mss.grab(虚拟屏)` → `cv2.cvtColor(BGRA2BGR)` → `cv2.resize(SCALE_FACTOR=0.9)` →
  `cv2.imencode('.jpg', JPEG_QUALITY)` → 发送。帧率靠 `sleep` 控，**JPEG 整帧，没有 H.264/帧间压缩**。
- **输入**：`apply_event` 把远端的**归一化比例坐标**还原成虚拟屏像素
  （`virt_left + ratio * virt_width`），再 `pyautogui.moveTo/mouseDown/mouseUp/keyDown/keyUp/scroll/hscroll`。
  → **就是驱动真实系统光标**（pyautogui 内部 = `SetCursorPos` + `SendInput`）。
- **`FreezeWindow`**（它唯一"额外"的设计）：tkinter 无边框置顶窗（`overrideredirect` + `-topmost`，
  并用 `GetParent`/`GetWindowLongW`/`SetWindowLongW`/`SetWindowPos` 改窗口样式），
  尺寸取**物理屏**几何，显示**物理屏自己的静态快照**。效果：物理屏看起来"冻住"了，
  本机用户看不到后续变化、也点不动。由主控端热键触发。

**它没有的东西**（在 `agent.pyc` 里 grep 零命中）：剪贴板、文件传输、光标处理
（`cursor`/`SetCursorPos`/`GetCursorInfo` 全无）、服务/驱动安装、开机自启（"Startup" 的命中是
C 运行时的 `GetStartupInfoW`，不是启动文件夹）。

## 3. 主控端 `kz.pyc` 的思路

- 连服务器后先 `send_msg` 做**配对**（"配对成功，开始远程控制"/"配对失败"）。
- **`pynput` 装全局鼠标/键盘钩子**（`on_move`/`on_click`/`on_scroll`/`on_press`/`on_release`），
  并用 `keyboard.GlobalHotKeys` 注册全局热键 **`Ctrl+Shift+F` → 冻结画面**。
- **坐标归一化成比例**再发（`'%.4f'` 格式，分母是 `pyautogui.size()`），
  并且 **move / click / scroll 各自有独立节流间隔**（`move_interval`/`click_interval`/`scroll_interval`）。
- `_try_update_win_rect()` 用 **`cv2.getWindowImageRect("远程桌面")`** 取窗口内**真实图像矩形**
  来校正坐标（去掉标题栏/边框的影响），注释写着"不要高频调用"。
- 收图在后台线程（`np.frombuffer` → `cv2.imdecode` → `frame_queue`），
  **GUI 在主线程**（`namedWindow`/`imshow`/`waitKey`，注释"必须主线程运行 cv2 GUI 循环"）。
- `key_to_pyautogui` 手写 38 个按键名映射；有**心跳线程**，服务器无响应就主动断开。

## 4. 结论：验证了什么、可以借鉴什么

### 它验证了本项目现在的方向
"本机已有的第二块（虚拟）屏给远端用 + 输入驱动真实系统光标"这条路是能跑通的，
而且它**完全不需要**新建账户/多会话/RDP。这与我方"共享模式 + 虚拟外屏 + 光标仲裁"一致。
更进一步：它**连"本机用户一动鼠标就把光标抢回去"这个问题都没处理**，我们的
`CursorArbiter` 已经比它多做了一步。

### 可以借鉴的 4 点
1. **坐标归一化成比例 + 主控端按窗口实际图像矩形校正**（`getWindowImageRect`）：
   比我们主控端手算 letterbox 留白更稳，窗口被拖动/最大化后也不会偏。
2. **每类事件独立节流**：省带宽，减少服务器与注入压力；我们目前是有事件就发。
3. **`FreezeWindow`（冻结物理屏）**：一个可选的产品能力 —— 远端接管期间把本机屏"冻住"
   （隐私/防误操作）。它和我们"本机用户不受影响"是互补的两种模式，适合做成开关。
4. **驱动安装路线**：它就是装 `usbmmidd`（`installer64 install usbmmidd.inf`）。
   我们现在的 MttVDD + nefcon 更现代，**不必换**；但若客户机器上 MttVDD 装不上，
   usbmmidd 可作备胎。

### 它明显不如本项目的地方（不必回退）
JPEG 整帧、无 H.264/无帧间压缩（带宽大一个量级）；**没有剪贴板、没有文件传输**（即本项目的 CV
能力它完全没有）；没有授权/防绕过；没有 P2P 直连；没有 TLS 和中继；主控端 GUI 就是一个
`cv2.imshow` 窗口；服务器 IP 硬编码在代码里。

### 注意
易语言那版主控端里带有 `http://e2eeE.com:8443`、`http://127.0.0.1:8984/solr/e2ee` 之类字符串，
属于它依赖的库/服务，**不要带进本项目**。

```bash

PY314=C:/Users/Panda/AppData/Local/Python/pythoncore-3.14-64/python.exe   # 本机自带 Python 3.14

$VP -m pyinstxtractor_ng "<某个.exe>"          # 解出 _extracted 目录（含入口 .pyc）
$PY314 build/pyrev/dump_pyc.py <入口.pyc> out.txt        # 分层列出函数/类/字符串常量/导入表
```
